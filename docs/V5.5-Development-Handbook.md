### 5.3 软删除 vs 硬删除

- **软删除** (4张)：`diaries`, `todos`, `work_plans`, `expenses` — `deleted_at` 字段，回收站支持恢复
- **硬删除** (其余)：直接 `DELETE`，不可恢复

## 第六部分：代码质量

### 6.1 当前已知问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **多处 `supabase as any`** | TypeScript 类型安全丧失 | 逐步替换为 typed client |
| 2 | **硬删除与软删除不一致** | 部分数据误删无法恢复 | 统一策略 |
| 3 | **Search.vue 全量加载** | 数据量大时首屏慢 | 前端切换 ilike |
| 4 | **批量操作 N+1** | 批量操作慢 | `Promise.all` 并发 |
| 5 | **无单元测试** | 回归风险 | 添加 Vitest |
| 6 | **无 CI/CD** | 手动部署 | Vercel Git 集成已可用 |
| 7 | **旅程节点不可编辑** | 用户无法自定义 | 需 time_profile 加 milestones JSONB 字段 |
| 8 | **暗色模式逐页未精调** | Hero/CSS 渐变在暗色下保持亮色 | 逐页适配 CSS |

### 6.2 响应式断点

- AppLayout：`< 768px` → 移动端（底部导航），`>= 768px` → 桌面端（顶部全量导航）
- 各页面独立断点（400/480/599/600/767/768/1024）

```sql
CREATE TABLE IF NOT EXISTS public.xxx (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  -- 业务字段
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
ALTER TABLE public.xxx ENABLE ROW LEVEL SECURITY;
CREATE POLICY "xxx_select" ON public.xxx FOR SELECT  USING (auth.uid() = user_id);
CREATE POLICY "xxx_insert" ON public.xxx FOR INSERT  WITH CHECK (auth.uid() = user_id);
CREATE POLICY "xxx_update" ON public.xxx FOR UPDATE  USING (auth.uid() = user_id);
CREATE POLICY "xxx_delete" ON public.xxx FOR DELETE  USING (auth.uid() = user_id);
CREATE INDEX IF NOT EXISTS idx_xxx_user ON public.xxx(user_id);
```
