### 1.3 系统架构（文字版）

```
用户 (Browser)
  │
  ├─ index.html (暗色模式防闪烁脚本 + PWA manifest)
  │
  ├─ main.ts (Vue → Pinia → Router → Auth Init → mount)

  │     ├─ memory.ts ────── Supabase `memories` 表
  │     ├─ tag.ts ───────── Supabase `tags` + `diary_tags` 表
  │     ├─ student.ts ───── Supabase `students` 表
  │     ├─ schedule.ts ──── Supabase `schedules` 表
  │     ├─ asset.ts ─────── Supabase `assets` 表

  │
  └─ Supabase Cloud
        ├─ Auth (邮箱密码注册/登录)
        ├─ PostgreSQL (15张活跃表, RLS 策略)
        └─ Storage (bucket: `photos`, 公开访问)
```

### 1.4 数据流向

```
用户操作 → 页面组件 → Pinia Store → Repository → Supabase REST API → PostgreSQL
                                                    │
                                                    └─ Storage (图片文件)
```

- **认证流**：`main.ts` 启动时调用 `authStore.initialize()` → Supabase `getSession()` → 恢复登录状态
- **数据加载**：页面 `onMounted` 检查 Store 是否已有数据，没有则调用 `loadXxx()`
- **数据保存**：Repository 层获取 `auth.getUser()` 得到 `user_id`，写入时自动关联用户
- **图片上传**：`DiaryPhotoRepository.uploadDiaryPhoto()` → Supabase Storage bucket `photos` → 路径 `{userId}/diary/{diaryId}/{timestamp}.{ext}` → 返回 public URL → 存入 `diary_photos` 表
- **无实时同步**：所有数据操作均为请求-响应模式，无 WebSocket/实时订阅

### 2.2 核心文件说明

| 文件 | 作用 |
|------|------|
| `src/main.ts` | 应用启动：暗色模式恢复 → Pinia/Router → Auth Init (6秒超时) → mount |
| `src/App.vue` | 根组件：`/login` 全屏渲染，其他路由按 `appStore.isMobile` 分发布局 |
| `src/router/index.ts` | 25条路由定义 + `beforeEach` 守卫 (requiresAuth → 跳登录，已登录走 `/login` → 跳首页) |
| `src/services/supabase.ts` | Supabase 客户端创建 + `signUpWithEmail/signInWithEmail/signOut/getCurrentSession` |
| `src/stores/auth.ts` | 认证状态 (user/session/profile) + displayName/displayBio computed + updateProfile (支持 avatar_url) |
| `src/types/database.ts` | 所有表的 TypeScript 类型定义，Repository 层通过 `Database['public']['Tables']['xxx']` 引用 |

### 2.3 样式系统位置

- **`src/styles/variables.css`**：100+ 个 CSS 自定义属性
  - 颜色：`--color-primary: #4A8C94` (湖绿), `--color-accent: #C2676A`, 暗色模式 `.dark` 覆盖
  - 圆角：`--radius-sm (8px)` → `--radius-2xl (32px)`
  - 间距：`--spacing-xs (4px)` → `--spacing-4xl (64px)`
  - 阴影：`--shadow-xs` → `--shadow-xl`
  - 字体：`--font-display (36px)` → `--font-caption (12px)`
- **`src/styles/global.css`**：全局重置 (box-sizing/body 字体/#app 最小高度)

## 第四部分：数据库和数据模型

### 4.1 数据库概览

| 属性 | 值 |
|------|-----|
| 类型 | Supabase PostgreSQL |
| 认证 | Supabase Auth (email/password) |
| 存储 | Supabase Storage (bucket: `photos`) |
| 安全 | Row Level Security (RLS), 每表 `auth.uid() = user_id` |

### 4.2 活跃数据表 (15张)

| 表名 | Repository | Store | 删除策略 | 用途 |
|------|-----------|-------|---------|------|
| `profiles` | 无 (auth store 直连) | `auth.ts` | — | 用户资料 (nickname/bio/avatar_url) |
| `time_profile` | `TimeRepository.ts` | `time.ts` | — | 支教主倒计时 (单行) |
| `countdowns` | `TimeRepository.ts` | `time.ts` | 硬删除 | 自定义倒计时 (pinned 置顶) |
| `diaries` | `DiaryRepository.ts` | `diary.ts` | 软删除 | 日记 |
| `diary_photos` | `DiaryPhotoRepository.ts` | — | 硬删除 | 日记内嵌图片 |
| `diary_tags` | `TagRepository.ts` | `tag.ts` | — | 日记-标签关联 |
| `tags` | `TagRepository.ts` | `tag.ts` | — | 标签定义 |
| `todos` | `TodoRepository.ts` | `todo.ts` | 软删除 | 待办 |
| `work_plans` | `WorkRepository.ts` | `work.ts` | 软删除 | 工作安排 (含 start_time/end_time) |
| `expenses` | `ExpenseRepository.ts` | `expense.ts` | 软删除 | 花费记录 |
| `schedules` | `ScheduleRepository.ts` | `schedule.ts` | 硬删除 | 课程表 |
| `students` | `StudentRepository.ts` | `student.ts` | 硬删除 | 学生档案 |
| `assets` | `AssetRepository.ts` | `asset.ts` | 硬删除 | 资产 |
| `welfare_items` | `WelfareRepository.ts` | `welfare.ts` | 硬删除 | 福利 |
| `memories` | `MemoryRepository.ts` | `memory.ts` | 硬删除 | 大事记 |

### 4.3 数据关系

```
profiles (1:1 auth.users)
time_profile (1:1 user)
countdowns (1:N user)
diaries (1:N user) → diary_photos (1:N diary), diary_tags (N:M tags)
work_plans (1:N user)
todos (1:N user)
expenses (1:N user)
schedules (1:N user)
students (1:N user)
assets (1:N user)
welfare_items (1:N user)
memories (1:N user)
```

### 4.4 RLS 策略模式

所有用户数据表使用统一 RLS 模式：
```sql
ALTER TABLE public.xxx ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users CRUD own xxx" ON public.xxx FOR ALL USING (auth.uid() = user_id);
```

例外：`diary_photos` 无 `user_id` 列，通过子查询关联：
```sql
USING (auth.uid() = (SELECT user_id FROM public.diaries WHERE id = diary_id))
```

### 4.5 软删除 vs 硬删除

- **软删除** (4张)：`diaries`, `todos`, `work_plans`, `expenses` — 通过 `deleted_at` 字段标记, 支持回收站恢复
- **硬删除** (其余)：`countdowns`, `diary_photos`, `schedules`, `students`, `assets`, `welfare_items`, `memories` — 直接 `DELETE`, 不可恢复

## 第五部分：代码质量检查

### 5.1 代码结构问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **Home.vue 内联实现过多** (~500行) — 快捷入口 SVG v-if 链 100+ 行, 3张今日卡片完全内联 | 维护困难, 与已有独立组件 (SummaryCard/QuickAction) 重复 | 用已有组件替换内联实现, 减少到 ~150行 |
| 2 | **32 处 `supabase as any`** 散布在 14 个 Repository 文件中 | TypeScript 类型安全完全丧失, Database 类型定义形同虚设 | 逐步替换为 typed Supabase client 调用 |
| 3 | **硬删除与软删除不一致** — 11张表中有7张用硬删除 | 数据误删无法恢复 | 统一为软删除或至少为关键表加确认对话框 |
| 4 | **重复的数据加载逻辑** — "Store 空则加载" 模式在 Home/Search/Statistics 中重复 | 代码冗余 | 抽取 `useDataLoad` composable |
| 5 | **getCountdownStats 无空值保护** — `new Date('' + 'T00:00:00')` = Invalid Date → NaN | UI 可能显示 NaN | 添加日期有效性检查 |

### 5.2 性能问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **Search.vue 全量加载** — `onMounted` 加载所有日记+工作进内存 | 数据量大时首屏慢, 内存占用高 | 考虑 Supabase 全文搜索或分页 |
| 2 | **批量操作 N+1** — `batchComplete/batchDelete/batchCreateStudents` 逐条 API 调用 | 批量操作慢 | 实现批量 API 端点或使用 `Promise.all` |
| 3 | **Expense 分组依赖预排序** — `groupedByDate` 要求数据已排序 | 数据乱序时出现碎片化分组 | 在 grouping 前显式排序 |
| 4 | **MemoryTimeline 全量加载照片和标签** — 所有记忆事件一次性查询 | 数据多时首屏卡顿 | 分页加载, 虚拟滚动 |

### 5.3 用户体验问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **响应式断点碎片化** — 9种不同断点 vs App Store 3种标准断点 | 中屏设备布局可能异常 | 统一为 768/1200 两个标准断点 |

### 5.4 数据安全问题
